# Workshop financial evidence bridge — candidate only

The canonical Soul Codex durable billing service now returns an internal reconciliation projection after existing transaction, receipt and grant persistence. The projection is not persisted or exposed by the four inspected HTTP callers, which discard the writer's result. It does not create a wallet, payment, settlement, entitlement or provider request. Existing billing and native flags, product IDs, schema, access rules and store configuration are unchanged. The Python offline consumer accepts only this narrow projection, rejects injected financial amounts and authorization, excludes sandbox and deduplicates exact events. It is not a settlement importer or live ledger.

Verified lifecycle state is not cash: Apple/Google/Stripe transaction rows contain no settled amount, fees, currency or actual refund amount. All are unknown, not zero. Independent provider settlement statements, a durable outbox with transactionally recorded reconciliation events, read-only authorized export, server-side tenant isolation and a production-grade transactional credit ledger remain mandatory before enabling money movement. This candidate is the first source-level interoperability boundary for the existing Workshop v0.3 engine. No live DB, provider, payment or user data used in tests. Test fixtures are isolated. Rollback: revert this draft's files, no migrations or production state changes.

Dedicated CI runs the pure projection and Python consumer tests. Existing product entitlement tests are extended for integration with the canonical writer using MemStorage; those are not live provider or Postgres tests.
