# Parent And Family Layer

Parents and family context belong in Soul Codex, but with strict boundaries.

Family data may describe imprint, environment, emotional climate, attachment pressure, survival style, and boundary formation. It must never define the user, excuse harm, create blame, or override the user's own profile.

## Locked Framing

```txt
Your parents' patterns may shape the emotional weather you grew up inside. They do not override your own chart. They help explain inherited pressure, attachment style, expectations, survival habits, and boundary wounds.
```

Short version:

```txt
Family context is shaping context, not destiny.
```

## What Belongs In This Layer

The parent/family layer may use:

- Parent signs and chart placements when provided.
- Parent numerology when provided.
- Parent Human Design signals when provided.
- Family structure.
- Caregiver behavior patterns.
- Emotional climate.
- Cultural or spiritual context.
- Economic or environmental pressure.
- Boundary patterns.
- Self-reported attachment and survival responses.

## What This Layer Must Answer

The family layer should help explain:

- What emotional climate did this parent or family system create?
- What did the user learn to hide?
- What did the user learn to perform?
- What boundary pattern formed?
- What survival strategy came from this?
- What should be kept?
- What should be released?
- What belongs to the user now, and what was inherited pressure?

## Boundaries

Do not say:

```txt
Your mother's sign made you this way.
```

Say:

```txt
If this parent expressed that pattern strongly, you may have learned to adapt around that emotional climate. This can shape your boundary reflexes, but it does not define your identity.
```

Do not use family data to:

- Blame a parent.
- Excuse abuse.
- Diagnose a family member.
- Tell the user what definitely happened.
- Override the user's lived experience.
- Claim the chart knows more than the user's memory or safety.

## Confidence

Family layer confidence depends on source quality:

- Verified: user supplied clear parent/family data and matching self-report context.
- Partial: some parent/family data exists, but behavior details are missing or uncertain.
- Unverified: family interpretation is based only on broad archetypes or incomplete data.

Family readings must always identify whether they are using computed data, user-reported behavior, or interpretive synthesis.

## Product Goal

The family layer should help the user reclaim agency.

It should move from:

```txt
This is what happened to you.
```

Toward:

```txt
This may be what you adapted to. Here is what you can keep, update, protect, or release.
```
